# Horizon Smart Home v1.1.1 — Performance and Stability Test Report

**Assessment date:** 17 August 2026
**Release under review:** `v1.1.1`
**Evidence scope:** Local static/build verification, native Linux package build, published GitHub Actions Windows NSIS build, and release metadata. This report does **not** represent a substitute for telemetry from production homes or a clean-device Windows endurance test.

## Executive Summary

The v1.1.1 release is **build-stable**: strict TypeScript validation, Vite production compilation, Rust compilation, local native Tauri packaging, and the hosted Windows NSIS release workflow all completed successfully. The public Windows installer was produced and published with a SHA-256 digest.

Runtime reliability is **not yet fully characterized**. The repository did not contain automated UI, integration, soak, startup-time, memory, or Home Assistant compatibility tests at the time of this assessment. Therefore, the correct conclusion is that the release is suitable as a **validated functional release candidate**, while field-operational stability remains an explicit follow-up requirement.

| Finding | Evidence | Impact | v1.1.2 response |

## Stability Findings

> **Validated:** reproducible dependency installation, static compilation, native packaging, and hosted Windows NSIS generation.
>
> **Not yet validated:** long-duration Windows runtime stability, CPU/memory profile, cold-start time, Home Assistant permissions matrix, network loss/reconnect behavior, installer/uninstaller behavior on a clean Windows machine, and external-device compatibility.

The Home Assistant integration stores credentials in process memory and clears them on disconnect or exit, reducing persisted-secret exposure. However, it needs real-device tests for invalid tokens, unreachable hosts, non-HTTPS endpoints, service failures, and entities that change while the app is open. Home Assistant’s REST API provides the state and service interfaces used by the current integration. [2]

## Conclusion

v1.1.1 successfully passed **build and packaging verification**. It should not yet be described as empirically proven for long-term runtime stability or forecasting accuracy. Version v1.1.2 should add deterministic unit tests for the new forecast engine, a clear forecast confidence model, user-controlled dashboard customization, and the documented integration contract; the next release gate should include a clean Windows installation test and a real Home Assistant test instance.
